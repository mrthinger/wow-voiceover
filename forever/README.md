# VoiceOver for WoW Forever

Extends [VoiceOver](https://github.com/mrthinger/wow-voiceover) to the WoW
Forever client (codename Camelot, `wow_classic_beta`, 1.60.x, addon interface
16001) with audio generated by a local text-to-speech model instead of
ElevenLabs.

## How it fits together

WoW Forever runs the Retail engine, so the unchanged `AI_VoiceOver` player addon
already works there through its Mainline code path. Two things are new:

- `AI_VoiceOver/Capture.lua` (loaded by `AI_VoiceOver_Camelot.toc`) records every
  quest and gossip text you see, plus who said it, into the saved variable
  `VoiceOverCaptureDB`, and notes whether a sound pack already had audio for it.
- `AI_VoiceOverData_Forever` is a data module in the same format as the Vanilla
  pack. It only needs to hold what the Vanilla pack lacks: new Forever content
  and quests whose text changed. Its priority is higher than Vanilla, so revised
  lines win.

Quest and gossip text are not in the client files; the server sends them and the
client caches only what you have seen. So the workflow is a loop:

1. Play. Every quest you accept, hand in, or every NPC you talk to is captured.
2. Log out (the file is written on logout), then run `ingest.py`.
3. Run `generate.py` to synthesise everything still missing and rebuild the
   module's lookup tables.
4. Restart the client (new sound files are only seen at launch) and play on.

The beta client currently does not read saved variables back, so every session
starts empty; `ingest.py` merges sessions on disk, which is why it should run
after each logout (the `.bak` file gives one session of slack).

## Setup (NixOS)

```bash
nix shell nixpkgs#python312 nixpkgs#uv -c sh -c \
  'uv venv --python $(which python3) .venv-tts && VIRTUAL_ENV=$PWD/.venv-tts uv pip install -r forever/requirements.txt'
./forever/run.sh python forever/tts_smoke.py        # should report CUDA and write forever/smoke.wav
```

`forever/run.sh` wraps commands with the venv and the shared libraries that pip
wheels expect (libstdc++, zlib, libcuda) plus ffmpeg. Symlink the addon folders
into the beta client:

```bash
B="$HOME/Faugus/battlenet/drive_c/Program Files (x86)/World of Warcraft/_classic_beta_/Interface/AddOns"
ln -s "$PWD/AI_VoiceOver" "$B/AI_VoiceOver"
ln -s "$PWD/AI_VoiceOverData_Forever" "$B/AI_VoiceOverData_Forever"
ln -s "<path to>/AI_VoiceOverData_Vanilla" "$B/AI_VoiceOverData_Vanilla"   # the CurseForge Vanilla pack
```

## Voices

`generate.py` picks a `race-gender` voice per NPC (game objects and items use
`narrator`) and clones it from `forever/voices/<race>-<gender>.wav`.
`build_voice_references.py` assembles those clips from the client's own audio:
NPC hello/goodbye lines for the classic races, and the player vocal lines for
the Skyborne (ChrRaces 95 High Order and 96 Windshaper). Provide your own
`narrator.wav` (any 10 to 20 s clean recording) for the narrator voice.

## Data sources

- Client tables (DB2) and files come from [wago.tools](https://wago.tools):
  `https://wago.tools/db2/<Table>/csv?build=1.60.1.69913` and
  `https://wago.tools/api/casc/<FileDataID>?version=1.60.1.69913`. `wowdata.py`
  caches them under `forever/data/db2/`.
- NPC race and gender: the addon reads the creature's display ID through a
  hidden PlayerModel; `CreatureDisplayInfo` -> `CreatureDisplayInfoExtra` gives
  `DisplayRaceID` / `DisplaySexID`.

## Commands

```bash
./forever/run.sh python forever/ingest.py                 # merge WTF saved variables into forever/data/capture.json
./forever/run.sh python forever/generate.py --dry-run     # what would be generated, with which voice
./forever/run.sh python forever/generate.py --limit 10    # try a handful
./forever/run.sh python forever/generate.py               # everything missing, then rebuild tables
./forever/run.sh python forever/generate.py --tables-only # rebuild lua tables from files on disk
./forever/run.sh python forever/build_voice_references.py skyborne human
```

In game: `/vo` opens VoiceOver's options, `/vocapture` prints what this session
has captured so far.
